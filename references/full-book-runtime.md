# 整书自动运行协议

## 宿主探测与运行策略

开始新书的生产动作前，检查当前会话实际暴露且当前任务可用的能力：工作区读写、脚本执行、子代理派发、子代理是否为新上下文、能否写入共享工作区、AI 助手 是否能开启新对话并在新对话恢复工作区，以及是否已有可用 OCR 工具和支持语言。只记录可见证据，不把“可能可以安装”当成已可用。用户尚未同意前，不为本书搜索、安装或运行新的 OCR 工具。上下文窗口政策只在宿主明确提供时记录；未公开时写 `unknown`，不根据一次压缩或中断推断硬上限。能力变化或换宿主后重新探测。

将结果写到工作区根目录 `runtime-strategy.json`，以 `assets/runtime-strategy.template.json` 为模板。至少保留以下字段：

- `schema_version`、`workspace`、`recorded_at_utc`：策略版本、工作区绝对路径和记录时间。
- `host.product` 与 `host.capabilities`：宿主标识及 `filesystem.read/write`、`script_execution`、`subagent.available/fresh_context/shared_workspace/permitted_for_task`、`ocr.available` 的布尔值；未确认的能力用 `null`。`ocr.languages` 记录已确认支持的语言，`ocr.evidence` 记录可验证的工具名或能力来源。`permitted_for_task` 记录本次任务是否允许委派。
- `host.capabilities.conversation_management`：记录 AI 助手 能否自行开启新对话、能否在新对话中恢复同一工作区，以及可见证据；与子代理能力分开判断。
- `host.context_policy.kind`：`auto_compaction`、`hard_limit`、`stateless` 或 `unknown`，并记录证据。
- `routing.mode`：`A`、`B` 或 `C`，以及 `reason`、`writer_dispatch` 和回退模式。A 需要可用、具备新上下文、共享工作区且本次任务允许委派；B 需要磁盘流；无工具宿主使用 C。
- `continuation`：选择 `mode`（`agent_managed`、`same_conversation`、`user_handoff` 或 `unknown`）、`handoff_trigger`（`none`、`context_limit`、`each_chapter` 或 `unknown`）、用户要携带的材料、普通中文说明和证据。不能确定时使用 `unknown` 并在开工前讲清不确定之处，不要假设 AI 助手 可以自行开新对话。
- `context_contract`：限定当前动作输入、允许的跨章摘要，并明确默认不载入前序章节完整原文或长篇译文。回源核验所需的当前章节原文除外。
- `recovery`：状态文件和总控入口。它们用于重建断点，不代表后台服务或应用关闭后的自动执行。

若 `runtime-strategy.json` 缺失或路由未选定，总控先返回 `host-probe` AI 助手 动作；AI 助手 填写策略文件后再运行总控。损坏的 JSON 不静默覆盖，先报告并保留现场。宿主无法写入文件时使用模式 C 的文本交接卡，并如实说明自动恢复不可用。

宿主探测完成后，AI 助手 必须先用普通中文告诉用户本次协作方式：哪些能力足以让当前会话继续推进、进度保存在哪里、AI 助手 能否自行切换新对话、是否需要用户在章节边界或上下文受限时手动携带交接材料，以及宿主停止后不会后台继续。不要向用户输出 A/B/C、JSON 字段或内部命令作为解释。不能把“整书翻译”的任务目标说成一次上传后必然自动完成。

运行策略是工作区元数据，不加入章节内容的哈希门禁；改变宿主策略不应使已完成的语义审核失效。

## 主循环

1. AI 助手 从原书创建独立工作区，intake_book.py 读取材料、建立章节与配置。查看摄入报告，判断语言、编码、目录和页面文本。低置信度自动回读正文纠正，不让用户选语言。扫描 PDF 或图片页无法读取时暂停，并按下方 OCR 同意流程处理。
2. 调用 orchestrate_book.py。脚本自动执行有限个确定性步骤，然后返回 agent 动作，或 all_done:true。
3. 对 agent 动作读取 inputs，遵照 instructions 产出 expected_outputs，必要时执行 prepare_commands。完成一个动作后继续调用总控。总控的角色描述是本技能内部任务，不是用户需要复制的提示。
4. 按 `runtime-strategy.json` 路由 writer 动作。模式 A 可交给无父历史的独立子代理，只传列出的中文输入并让产物直接落盘；不得把源文、抽取清单的源句列或审计报告塞进写作者。模式 B 由当前 AI 助手 按阶段写作与核验。模式 C 逐章或按已说明的边界生成有限的手动交接卡，并告诉用户要把哪些材料贴到新对话。模式未知时先完成宿主探测；不得假定已隔离，也不得把内部阶段交接误交给用户。
5. 章节顺序提交台账与实际总结。末章自动汇编并检查输出。随后由 AI 助手 查看实际导出的 Word 排版，必要时修正并重新汇编；只有成品与实际范围一致时才交付。

动作含 kind（tool/agent）、stage、role、instructions、inputs、expected_outputs、commands 与 prepare_commands。commands 是解释器和参数数组，不包含 shell 片段。主 AI 助手 可使用宿主工具运行它们，不用 eval 字符串或只把它们展示给用户。Python 不能直接调用任意宿主的模型工具，派发和等待由主 AI 助手 实际完成。

## 细读与完整性

P7 不只记录结论，包含原作全部实质材料。每个源段须被安排或明确属于纯标题/版面噪声；正文事实、例子和论述不得作为“非核心”排除。P8 先回读源文，检查清单是否漏掉内容，再核成稿。覆盖 100% 是机械证据齐全，不证明语义正确，实际语义仍由回源者负责。

整合可去无功能接缝，不能压缩原作铺陈。改变正文后更新受影响证据，不改审计来掩盖缺失。普通风格、篇幅和模型候选别名是提示，不阻断；缺页、空章、改义、引文不实或用户明确禁用的表达属于实际错误。

## 摄入、图表与注释

EPUB 按 spine 顺序读，目录与非线性注释也要判读，不能按压缩包名称排序。文本 PDF 优先读取文字；扫描页尝试本机可用 OCR。自动检测不能解决的扫描语言由 AI 助手 阅读页面决定再重试 OCR。OCR 缺工具或语料时如实指出，不把非空文本当作页面完整。

### 图片 PDF 的用户沟通与 OCR 续接

当错误明确显示 PDF 页面是图片且当前环境不能提取文字，或 OCR 工具/语言数据缺失时，不要把它说成普通“程序报错”。先停下摄入并向用户说明：当前文件有图片页，AI 助手 不能直接读取其中的正文，翻译前需要把页面扫描成文字；询问用户是否同意 AI 助手 检查现有工具/技能，必要时寻找可信的开源 OCR 方案并把 PDF 转成文字版 Markdown。也告知用户可以改用其他更经济的扫描工具。不得在用户同意前联网寻找、安装或运行新的 OCR 工具。

用户同意后，先检查 AI 助手 当前可用的本地工具、已安装技能和依赖，再选择能在本机运行、来源清楚且支持原文语言的方案；必要时搜索官方或项目维护者文档，试跑少量页面并核对文字与页码后再处理全书。原 PDF 保持不变。将 OCR 正文保存为 UTF-8 Markdown，尽量保留页码、章节和版面顺序；另记 OCR 工具/版本、处理页数、语言及未识别页。逐页抽查；不清楚的部分标成待核，不能凭上下文补成原文。

如果当前 AI 助手 能读写同一工作区、并能在当前会话继续或自行切换到可恢复的新上下文，使用 OCR Markdown 重新运行摄入，按正常流程继续；需要切换时先读取策略、书籍状态和 OCR 记录，不让用户搬运内部阶段交接。若 AI 助手 不能自行开启必需的新对话，或当前环境不能持久化/继续，则生成两个可独立复制的材料：完整 OCR 文字版 Markdown，以及明确要求从该 Markdown 重新摄入并继续全书流程的专用交接 Prompt。告知用户在新对话同时提供两份材料。若 Markdown 太长而宿主不能附加文件，要分段编号并说明顺序；不得只交一个泛化提示或把 OCR 文本截断后称为完整。

正文引用的图表、公式和注释要回到原 EPUB 成员或 PDF 页查看，必要时提取图片嵌入或保留可读的原式并加说明。不凭纯文本猜复杂表格关系。当前脚本保留文本和图示占位用于定位，复杂图像/公式仍需要 AI 助手 的页面工具或 OCR；不可读部分不能悄悄省略后宣布完整交付。

## 安装副本的本地适配

每本书的路线先记录在工作区 `runtime-strategy.json`。如果同一宿主的限制会反复改变技能的可执行方式，并且已核实技能安装目录及写权限，可以按 `SKILL.md` 的授权在该安装副本中做最小适配。优先写入 `references/host-adaptation.local.md`，保留通用入口和质量标准，记录适配依据、日期和恢复方式。下次运行时先读取此文件。安装目录不明或只读时，不要修改猜测位置；只使用本书运行策略。此本地文件不得进入公共 ZIP。

## 修复与恢复

总控绑定已有产物与输入检查结果。抽取错误重抽对应段；成稿错误局部修正；多个意义单元混淆时缩小任务。纯提示无需重跑所有阶段。同一策略失败反复时换策略，不原样无限重试。文件损坏、输入加密、宿主中断等客观不可解问题报告具体原因，不生成假内容。

上下文压缩或会话恢复后，先读 `runtime-strategy.json`、本工作区 `book.json`，再运行 `chapter_status.py` 检查当前章节断点并调用 `orchestrate_book.py`；只重建当前现场，不重做已通过阶段。不要因压缩本身停下等待用户指令，也不要宣称脚本会在 AI 助手 宿主停止后后台运行。技能不自行建立新聊天、常驻进程或收费模型网关。
