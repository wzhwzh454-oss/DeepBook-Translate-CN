# 全书架构规划 · P0

为外文学术书籍规划中文研读改写与翻译的全书脉络。
输入是全书各章标题、目录、引言/导论摘录以及可选的预设词表。

目标是准确建立整本书的宏观论证弧线（Argument Arc），明确各章节在全书体系中的逻辑承接关系，防止各章成为互不相连的孤岛。

先为全书选择一个 `genre_family`：`analytic_arg`（分析论证）、`humanities_scholarly`（人文社科思辨）、`continental_critique`（欧陆思想/批评理论）、`narrative_nonfiction`（叙事非虚构/历史传记）或 `literary_fiction`（严肃文学/艺术散文）。现代白话是共同底盘，体裁只调整叙述呼吸、解释密度、案例处理和标题策略。不要把文学或叙事书强行改成教案。

## 输出要求

按如下格式输出（用 `- ` 起首）：

# 全书头部
- 书名（中文与原文）：中文暂定译名 / 英文原名
- 作者（中文与原文）：中文通行译名 / 英文原名
- 全书核心问题：一句话界定本书试图回答的根本问题
- 全书总主张：一句话归纳作者的最终核心立场
- 论证推进弧线：分阶段说明全书如何从问题出发、辨析概念、展开主要论证、击破对立异议并得出结论
- 全书总章数：N 章
- 文风与体裁基调：genre_family；一句话说明现代白话底盘上的体裁侧重
- 将 `genre_family` 和简短的 `description` 写入 `book.json` 的 `style_profile`，供后续章节任务单沿用

### 第 k 章：章节名称与功能定位
- 章节标题：原标题与中文暂定名
- 本章子问题：本章旨在解决什么具体问题
- 承担的承接链段：问题提出／概念铺垫／核心推导／经验案例／反驳辩护／拓展总结
- 核心预设与依赖：依赖前文哪些章节的结论
- 预期向后移交的问题：本章预计会给下一章抛出什么悬念或未决问题
- 预估源文字数：约 N 词
- 预估分节数：建议切分为 M 个研读子节
