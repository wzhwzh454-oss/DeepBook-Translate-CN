# 术语与概念依赖计划 · S1.5

v3 的普通译名由你按语境定稿，collision 记录歧义和解决依据，不要求每次用户确认；已有用户锁定词仍尊重。对容易混用的词分清概念而非只统一字面：同形异义（如不同学科里的 category）要用 `collision` 写明义项区分；近义术语对（如 X condition 与 X dependence）分别定名，定义不能抄成某个模型主张；同一术语在全书保持同一译名。以上不压过作者的实际用法或用户已明确的译名。

输入只含大纲、编号源文和可选锁定词表。术语台账不是出场计划：本次要说明读者先懂什么，才能理解后面的词。不要把领域常识或你自己的例子写成作者内容。

输出一个 JSON 对象：`{"version":2,"terms":[...],"user_banned":[...]}`。每项有 `id`（T1 等）、`zh`、`orig`、`level`（核心/辅助）、`gloss`（约25字的日常说法）、`role`（约30字，本文为什么需要此词）、`example_src`（原文已有例子的 [Pn]，无则 null）、`depends_on`（id 数组）、`first_section`（教学节号）、`confusable_with`（id 数组）、`alias_ban`（字符串数组）。
- `alias_ban`：模型识别出的潜在混淆候选词，供后续上下文与源文细读复核（仅作为 advisory 提示，不能当作硬性用户禁令）。
- `user_banned`：可选字符串数组，仅用于填入用户明确禁用的表达（可置于顶层或具体术语中，只有用户明确禁用的表达才触发阻断性违规）。
- `collision`：可选字段，用于记录译名与其他领域的冲突与定名依据；废除旧有必须等待用户逐词批准的 `collision_confirmed` 限制，已有锁定译名保持锁定不解锁。

**沿用已锁定术语**：本章要用到的 ledger 术语以 `"inherited":true`、`first_section:null` 写入（译名必须与台账完全一致，脚本核对漂移）。**跨章依赖**写 `c01:T3` 或 `ledger:<中文译名>`，不要写裸 `T1`（裸 id 只指本章）。同一中文名对应两个原词时必须写 `collision` 说明义项。依赖须无环，先决概念不能安排在后节。每节新增核心术语以4个为初始目标；超过时提出拆步或提前补充建议，不删除必要概念。辅助层的提前介绍不等于忠实层已完成首现解释。并列概念尽量对称命名，但锁定译名优先。锁定条目不改名、不遗漏；同义词归并，确有多义时明确区分词项，不能为了满足一一对应而混合意义。

首现材料包含日常说法、本文作用、原文例子或有出处的回指。原文无例子时，不编造忠实层例子；可登记需要背景小卡。教学类比默认关闭。计划不决定原文主张强度。中文释义与译注优先直接陈述，能自然表达时少用“不是……而是”“不仅……还”等固定格式和冒号、分号、破折号；这项偏好不改变术语关系或原文逻辑。



原词语言以 source_lang 明确标注。按 references/terminology-grounding.md 对核心术语按需考据；authority_sources、translation_note、analogy、orig_aliases 可选，没查过不编来源，不要求用户审批。无需术语的材料可使用 terms:[]，不为满足表格造词。
